1 · System Overview

Q-SAT is an end-to-end research simulation and adaptive control platform that models a Low Earth Orbit (LEO) satellite transmitting polarised single-photon pulses to an Optical Ground Station (OGS) using the BB84 Quantum Key Distribution (QKD) protocol. The system consists of three major runtime components that work together:

┌────────────────────────────────────────────────────────────────────┐ │ Q-SAT RUNTIME COMPONENTS │ ├────────────────────────────────────────────────────────────────────┤ │ │ │ ① FASTAPI BACKEND ─────────────────────────────── port 8000 │ │ Python 3.12 · Uvicorn ASGI · REST + WebSocket │ │ Digital Twin · BB84 QKD Engine · AI Controllers │ │ SQLite database (qsat.db) │ │ │ │ ② ANGULAR DASHBOARD ───────────────────── /dashboard/ (built) │ │ Angular 22 · TypeScript · ECharts │ │ Served statically from the backend at /dashboard/ │ │ OR via Angular dev server at port 4200 (development) │ │ │ │ ③ MQTT BROKER (optional, HIL mode only) ──────── port 1883 │ │ Eclipse Mosquitto 2.0 (Docker or native install) │ │ Only required when ENVIRONMENT_MODE=mqtt │ │ │ └────────────────────────────────────────────────────────────────────┘

In the default simulation mode, only the backend is required — the Angular frontend is built once and served by FastAPI. No external database server, Redis, or MQTT broker is needed for standard operation.

3 · Step-by-Step Installation

1
Install Python 3.12

Download the official installer for your OS from python.org/downloads.

Windows

  1. Download python-3.12.x-amd64.exe from python.org.
  2. Run the installer. On the first screen, check "Add Python to PATH" before clicking Install.
  3. Select "Install for all users" for system-wide availability.

Linux (Ubuntu / Debian)

sudo apt update
sudo apt install -y software-properties-common
sudo add-apt-repository ppa:deadsnakes/ppa -y
sudo apt install -y python3.12 python3.12-venv python3.12-dev

macOS

# Using Homebrew
brew install python@3.12

Verify installation

python --version
# Expected output: Python 3.12.x
2
Install Node.js 20 LTS

Download the official LTS installer from nodejs.org/en/download. Choose the LTS channel (v20.x).

Windows

Download and run the node-v20.x.x-x64.msi installer. Accept defaults — npm is included automatically.

Linux (Ubuntu / Debian) — via NodeSource

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

macOS

brew install node@20
brew link --overwrite node@20

Verify installation

node --version    # Expected: v20.x.x
npm  --version    # Expected: 10.x or 11.x
3
Get the Project Source Code

Option A — Clone with Git (recommended)

git clone https://github.com/your-org/q-sat.git
cd q-sat

Option B — Extract from ZIP archive

Unzip the provided Q-SAT-source.zip to a folder of your choice, then open a terminal in that folder.

ℹ
Project root from here on

All commands in this guide are run from the project root directory (the folder containing backend/, frontend/, .env.example, etc.).

4
Create a Python Virtual Environment

A virtual environment isolates project dependencies from your system Python.

Windows (PowerShell)

# Create the virtual environment
python -m venv .venv

# Activate it
.\.venv\Scripts\Activate.ps1

# If you get an execution policy error, run this first:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Linux / macOS

python3.12 -m venv .venv
source .venv/bin/activate

Your terminal prompt will now show (.venv) to confirm the environment is active.

!
Always activate the venv before running Q-SAT

You must activate the virtual environment every time you open a new terminal session before running any Python commands for this project.

5
Install Python Dependencies

With the virtual environment active, install all required Python packages:

# Upgrade pip first
pip install --upgrade pip

# Install all project dependencies
pip install -r backend/requirements.txt
⏱
This step takes 5–15 minutes

PyTorch (≈2.5 GB download) is the largest dependency. Ensure you have a stable internet connection. Progress is shown in the terminal.

CPU-only PyTorch (faster download, ~500 MB)

If you don't have a CUDA GPU, you can install the lighter CPU-only build first:

pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r backend/requirements.txt

Verify

python -c "import fastapi, torch, skyfield; print('All core packages OK')"
# Expected: All core packages OK
6
Install Node.js Dependencies & Build the Angular Frontend
# Navigate to the frontend directory
cd frontend/qsat-dashboard

# Install all Node.js dependencies (uses package-lock.json for exact versions)
npm ci

# Build the Angular application for production
npm run build

# Return to project root
cd ../..   # Windows: cd ..\..

The build output is placed at frontend/qsat-dashboard/dist/qsat-dashboard/browser/. The FastAPI backend auto-detects and serves this at /dashboard/.

ℹ
Build takes ~2 minutes

Angular's build compiles TypeScript, bundles assets, and optimises for production. This only needs to be done once (or after frontend code changes).

7
Create the Environment Configuration File (.env)

Copy the provided template to create your local configuration:

Windows (PowerShell)

Copy-Item .env.example .env

Linux / macOS

cp .env.example .env

The default .env settings work out of the box for simulation mode. Edit .env only if you need to change ports, ground station coordinates, or switch to MQTT hardware mode. Key settings:

4 · Running the Application

4a. Start the Backend Server

Make sure your virtual environment is active, then run from the project root:

Production / Stable Mode

# Activate venv first (if not already active)
# Windows:  .\.venv\Scripts\Activate.ps1
# Linux/Mac: source .venv/bin/activate

python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000

Development Mode (auto-reload on file changes)

python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload

You will see startup output similar to:

INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO     qsat.main: Starting Q-SAT Adaptive Ground Station v0.1.0 in [simulation] mode
INFO     qsat.main: Ground Station: Lat=10.7905, Lon=78.7047, Alt=80.0m
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
✓
The backend is running when you see "Application startup complete"

Keep this terminal open. Press Ctrl + C to stop the server.

4b. Verify the Backend is Running

Open a new terminal (keep the server running) and test the API:

# Windows PowerShell
Invoke-WebRequest -Uri http://localhost:8000/ | Select-Object -ExpandProperty Content

# Linux / macOS
curl http://localhost:8000/

Expected JSON response:

{"message": "Welcome to Q-SAT Adaptive Ground Station", "version": "0.1.0", "docs": "/docs"}

4c. Open the Web Dashboard & API Docs

Open any modern web browser and navigate to these URLs:

🖥️   Mission Control Dashboard:   http://localhost:8000/dashboard/
📖   Interactive API Documentation (Swagger):   http://localhost:8000/docs
📖   Alternative API Docs (ReDoc):   http://localhost:8000/redoc
🔌   WebSocket live telemetry:   ws://localhost:8000/ws/live
ℹ
Dashboard requires the Angular build (Step 6)

The dashboard is only available at /dashboard/ if you completed the Angular production build in Step 6. If you skipped that step, use the dev server method described in Section 4d below.

4d. Run with Angular Dev Server (Development / Optional)

If you want hot-reload during frontend development, run the Angular dev server in a second terminal (keep the backend running in the first):

# In a NEW terminal window (backend stays running in the other)
cd frontend/qsat-dashboard
npm start   # runs: ng serve

Then open:

🖥️   Angular Dev Dashboard:   http://localhost:4200

The Angular dev server proxies API calls to the backend on port 8000 automatically.

6 · Hardware-in-the-Loop Mode (Optional)

In MQTT mode, the backend reads live environmental data from a physical ESP32 microcontroller via an MQTT broker instead of using the stochastic simulation.

Step 1 — Start Eclipse Mosquitto MQTT Broker

Using Docker (easiest)

docker run -d --name qsat-mosquitto -p 1883:1883 eclipse-mosquitto:2.0

Native Windows install

Download the installer from mosquitto.org/download, install it, then start the service:

net start mosquitto

Step 2 — Switch to MQTT Mode

Edit your .env file:

ENVIRONMENT_MODE=mqtt
MQTT_BROKER=localhost
MQTT_PORT=1883

Step 3 — Flash ESP32 Firmware

Follow the wiring and firmware guide in docs/hardware_integration.md. The ESP32 publishes JSON telemetry to the qsat/environment MQTT topic at 1 Hz.

Step 4 — Run the Software Emulator (no physical hardware)

python hardware/esp32/emulator.py --broker localhost --profile nominal
# Available profiles: nominal, storm, night, haze, clouds

Step 5 — Start the Backend

python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000

The status indicator in the dashboard will show HARDWARE instead of SIMULATION.

7 · Docker Deployment (Optional)

Docker Compose runs the backend and MQTT broker in isolated containers. Requires Docker Desktop to be installed and running.

Step 1 — Build the Angular Frontend First

cd frontend/qsat-dashboard
npm ci
npm run build
cd ../..

Step 2 — Create a Backend Dockerfile

Create the file backend/Dockerfile with the following content:

FROM python:3.12-slim

WORKDIR /app
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000
CMD ["python", "-m", "uvicorn", "backend.app.main:app", \
     "--host", "0.0.0.0", "--port", "8000"]

Step 3 — Start All Services

docker-compose up --build

# Run in background (detached mode)
docker-compose up --build -d

Step 4 — Stop All Services

docker-compose down
ℹ
Docker exposes backend on port 8000

After docker-compose up, access the application at http://localhost:8000/dashboard/ — the same URLs as the manual setup.

10 · Troubleshooting

✗
Error: "python is not recognized" / "python3: command not found"

Cause: Python was not added to PATH during installation.

Fix (Windows): Re-run the Python installer, choose "Modify", and check "Add Python to PATH". Or manually add C:\Users\YourName\AppData\Local\Programs\Python\Python312\ to your PATH environment variable.

Fix (Linux): Use python3.12 explicitly, or add an alias: alias python=python3.12

✗
pip install fails: "Could not build wheels for ..."

Cause: Missing C++ build tools for compiling native extensions.

Fix (Windows): Install Microsoft C++ Build Tools — select "Desktop development with C++".

Fix (Linux):

sudo apt install -y build-essential python3.12-dev
✗
PowerShell: "cannot be loaded because running scripts is disabled"

Cause: Windows execution policy blocks .ps1 scripts.

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Then re-run .\.venv\Scripts\Activate.ps1.

✗
Port 8000 is already in use

Fix: Either stop the process using port 8000, or change API_PORT in your .env file to another value (e.g., 8001), then restart.

# Find what's using port 8000 (Windows)
netstat -ano | findstr :8000
# Linux / macOS
lsof -i :8000
✗
Dashboard shows "404 Not Found" at /dashboard/

Cause: The Angular build was not run (Step 6 was skipped), so the dist/ folder doesn't exist.

Fix:

cd frontend/qsat-dashboard
npm ci
npm run build
cd ../..

Then restart the backend server.

✗
npm error: "node_modules" not found / Angular CLI not found

Cause: Dependencies haven't been installed yet.

cd frontend/qsat-dashboard
npm ci   # or: npm install
✗
ModuleNotFoundError: No module named 'backend'

Cause: The backend is being run from the wrong directory, or the venv is not active.

Fix: Always run uvicorn from the project root directory (not from inside backend/), with the venv active.

# CORRECT — from project root
python -m uvicorn backend.app.main:app --port 8000
!
PyTorch install is slow or times out

PyTorch is a large package (~2.5 GB). If the download times out, retry the install:

pip install -r backend/requirements.txt --timeout 120

Or install CPU-only torch first to reduce download size:

pip install torch --index-url https://download.pytorch.org/whl/cpu
